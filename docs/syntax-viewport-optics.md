# 句法23：让标注跟得上排版，让光留在空隙

## 本轮解决的问题

固定约480字符的阅读窗口在窄视窗、大字号下可能远高于可视区，始终不能满足70%可见条件。本轮保留原有稳定窗口，只在其排版高度超过当前可视区、且不能满足可见条件时，按原文从句、词和字素边界惰性细分。子窗口继承原句起止信息和完整的前后语境；公式与代码原子边界仍被保护。普通句子只是滑到屏幕边缘时不会被切成零碎片段。

每个子窗口仍需连续可见十秒。已有完成分析覆盖该子窗口时直接复用，在字号变化后不重复请求这部分；主动选区依旧可以明确发起新的分析。缓存中的旧光不会因为关闭设置就长期空白：覆盖面板真正移除、退场动画结束和排版参数改变后，重新测量当前原文。

## 跨行光路为什么要改变

一个大三次Bezier即使把两个控制点放在页边，曲线的中段也可能仍在文字区。此前的实现存在这个问题。本轮改为连续的分段路径：只在端点所在行的空隙向外延伸，在真实页边中转，再接回目标。可用位置由未选中的文字、公式、图片等实际占用范围共同确定，不能只看被标出的两个词。

没有足够页边空隙时，不强行把光线塞进正文，保留相关词的共色与共同相位。这样不会为了画一条线而破坏原文阅读。

第一版修正路径在截图里仍像半个段落边框，容易把控制关系误读为“整段属于某个作用域”。因此最终呈现让横向连接和端部进入透明，页边只留羽化的柔光；对应词保持呼应。页边渐变沿其实际纵向光路计算，避免沿两个词的直线坐标投影后，整段光路落到渐变范围之外。文字内容和字形布局未改变，没有箭头、节点或实体描边。

范围语义仍由模型的scope、perspective和within给出；程序不因排版范围相含就推断语义嵌套。窄视窗的固定检查例句采用“并非每一种变化都……”的外否定/内全称结构，验证的是既定关系的投影，不能用它评测模型的语言学能力。

## 已有证据

- 单元检查先复现了旧跨行曲线落入中间文字区的情况，修正后同一断言通过；另检查无空白走廊时保留词标而不强画连接，以及子窗口的稳定边界和原句语境。全部484项单元检查通过。
- 实际隐藏Electron检查：960×640窗口、24px字号时，480字符的旧窗口确实不可能满足70%可见面积；新的子窗口无需选择即进入模型队列并显影。
- 已完成的父窗口在缩窄/放大字号后不重新请求其子窗口，光层会在设置退场后恢复。这个检查曾暴露空白问题，修复了观察范围和重新测量时机后通过。
- 跨行控制关系在琉璃与潮光下都用实际原文矩形检查路径；暂停运动后关系仍在。截图等待显影opacity达到1，并保存实际计算样式，避免用“SVG节点存在”冒充光已经出现。
- 源码隐藏窗口13项通过，涵盖混排、公式、大字号、覆盖复用、跨行光路、候选读法、编辑撤除、流式首批显影、十秒准入、后台时间和错误保留。原文BOM/CRLF字节保持。所有接口响应为明确的固定测试数据，本轮无真实模型请求。

## 尚不能声称完成的部分

不同阅读窗口的图尚未自动融合；缓存父图的覆盖复用限于当前保留的条目。没有空白走廊时的共色/相位表达，以及多条关系的光学辨识度仍需要继续打磨。这里验证了漏标、排版恢复、路径与图形对齐，不代表任意文章上的语言学正确性或最终艺术质量已通过。

更新帮助22与数据保护工作保持原状，正式安装的生命周期隔离、恢复回滚与完整升级矩阵仍是发布阻断项。
