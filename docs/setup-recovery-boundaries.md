# 提交决定、终态重试与快捷方式撤回

39针对38交叉核对发现的恢复边界继续收口，当前仍属于实验安装流程。

## 不降级的提交决定

v2事务在程序、系统入口和回执完成核验后持久保存 `decision: commit`。恢复运行阶段可以变为 recovery-needed，但该决定不随一次守护启动或回执读取失败而消失。后续恢复继续完成原决定，不能把它重新当作未提交事务回滚。

已提交后重新取得守护时，安装版本目录和公开bootstrap均按已知程序文件核验，保留用户后来放入的文稿。未发布的暂存输入仍维持严格检查。用户提交后继续编辑文稿和设置不会被旧内容快照覆盖。

## 没有写入者记录时的同计划重试

完整提交清掉写入者记录后，同一原计划仍可由当前版本、原请求字段、v2日志、系统入口及原回执的文件身份和完整内容识别。完成结果只返回原事务，不重新创建安装、不删除占用的回执来重试。原回执被另一个文件替换，即使内容相同也会拒绝。

提交后的守护释放失败会返回错误并保留可收尾的事务，但不再把已写好的成功回执改成 incomplete。

## 撤回绑定到文件实体

公开快捷方式及暂存文件的撤回使用固定原生助手。助手打开同一文件实体并持有独占句柄，在句柄上核对NTFS卷、文件编号、独立链接数及默认流摘要，随后通过该句柄设置删除。检查之后被替换到原路径的新文件不因此被删除。相关接口语义见 [Microsoft的SetFileInformationByHandle说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)。

助手是源码中的小型C#程序，由Windows .NET Framework编译器构建，使用无控制台窗口目标；随包放在ASAR解包目录中，其固定位置列入程序文件归属清单。构建和测试入口会准备该助手，不依赖旧工作树里残留的二进制。

NTFS能力检查前置到快捷方式只读预检。目标不支持该撤回方式时，在新目录、发布记录和公开入口创建前就停止；不在产生副作用后才发现无法回滚。此阶段没有声称支持所有文件系统或所有NTFS附加元数据。

## 证据与边界

22项恢复相关检查通过，包含“已提交→首次恢复失败且进程退出→再次恢复仍完成同一版本”、公开bootstrap中新文稿保留、完整提交后释放失败的同计划重试，以及同内容替换回执拒绝。

9项原生文件与快捷方式检查通过，包含长Unicode路径、不同文件实体/原位修改/外来硬链接保留、撤回前原子替换公开路径的新文件保留，以及不支持介质的前置拒绝。介质拒绝时机使用能力结果替身；实际删除检查在本机NTFS运行，不把它描述为非NTFS实测。

真实进程场景采用隔离资料和隐藏运行。测试会先核对守护进程的路径和角色；如果它已经退出则直接验证重新取得守护，不对未知进程执行终止。最初的测试输出处理错误均保留现场并正常完成该事务、释放保护后再清理，没有重启覆盖未完成状态。

最终包的两条完整原生流程已串行通过：安装/卸载/重装回归8.3分钟，连续恢复失败与原计划重试7.2分钟，总计15.6分钟。后者确认守护丢失并再次恢复失败后仍保留commit决定，能重新取得原生保护、保留bootstrap旁新MD，再次执行已完成计划不重复安装。前者保留字体、加密配置、未命名草稿、后续71个profile文件与新改稿，移出158个归属明确的程序文件。测试全过程隐藏并使用隔离目录。
