# 背景动画：慢帧不应停止时间

琉璃、潮光及文稿光场共用 `MotionClock`。旧实现只累计不超过 250 毫秒的帧间隔；持续超过这个间隔时，回调和 GPU 绘制仍然执行，但动画时间完全不增长。

修正后，每个有效的可见帧都推进时间，单次最多推进 1 秒。普通慢帧不再被丢弃；异常长停顿不会导致一次追赶几十秒。隐藏、静态模式、重新挂载等已有明确暂停路径仍调用 `suspend()`，恢复后的第一个采样保留原相位。

## 验证口径

- 在原候选12中，普通多章节长文往返滚动未复现永久停帧；这不是对用户现场问题的否定。
- 将实际浏览器动画回调间隔控制为约 360 毫秒，保留真实时间戳和 GPU 绘制后，两个主题都重现动画时间不增长；修正后同样的场景通过。
- 新增长文滚动检查覆盖中途、末端和反向滚动后的动画时间、实际画面变化、图形错误及原文未变。
- 单元检查覆盖 1、2、3、4、15、60、144 Hz 采样、持续极慢帧，以及明确暂停与异常长帧的不同处理。

这些检查使用隐藏、不聚焦、独立配置的 Electron 实例。控制慢帧用于复现计时缺陷，不是屏幕帧率测量，也不证明用户现场只有这一个触发原因。没有调用真实模型，没有改变主题着色器、原文、AI协议或保存逻辑。
