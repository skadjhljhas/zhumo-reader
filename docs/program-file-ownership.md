# 程序文件归属与可恢复移除：候选24

本轮把“程序文件”和“用户保存的内容”分开处理。实现位于program-files.ts，已作为独立入口随包构建；它不是尚未完成的完整安装更新流程，也尚未接到正式卸载入口。

## 发行时建立依据

afterSign钩子在Windows图标/资源编辑、fuse和签名阶段之后生成program-files.v1.json。路径允许清单来自受信构建输入——Electron运行时文件列表、明确的应用包与项目resources，而不是扫描用户安装目录后将其中全部内容宣称为程序文件。混入未声明文件会使构建失败。Electron框架把LICENSE改名为LICENSE.electron.txt，已按构建工具的确定规则映射。

每项记录相对路径、长度与SHA256，并包含appId、版本、入口和平台。清单本身不计入其内容清单，独立构建回执留在输出目录外层。后续安装器必须从受信发行材料固定这个摘要；**安装目录里可被改写的清单或相邻摘要，不能自行充当信任来源**。

Windows构建禁止完全跳过资源编辑阶段；仅关闭代码签名可用signExecutable:false，仍运行生成清单的末尾阶段。生成清单不等于有了正式代码签名证书。后续发行校验仍须检查清单及最终exe/app.asar的实际内容。

beforePack先检查已有构建输出：必须有可核对的独立回执、匹配的发行身份，且无运行中的程序、修改文件、MD、未知内容或链接替换，才允许构建工具覆盖。没有回执的旧输出或不完整输出应保留并选择新目录；不为了重新构建而自动删除其中的数据。这个预检不是正式更新所需的全程互斥门禁。

## 判断与保留

审核核对清单固定摘要、安装目录中的发行身份，再按真实磁盘文件计算内容。它区分原版未改、已改、缺失、链接路径和未列入清单的内容。未声明目录不会被深入读取，只需原样留下；遇到Junction/符号链接不沿着它移动文件。路径穿越、大小写重复、Windows设备名、ADS路径语法和其他歧义路径均被拒绝。

retireProgramFiles只把仍与原版一致的程序文件移入程序目录之外、同卷、全新的可恢复暂存区。**MD/Markdown即使与随包原件相同，也保留在原位置。** 改过的文件、未登记的文稿和资源、链接及清单自身均不移走。不递归删除目录，也不删除暂存副本。

## 失败与恢复

每次移动前写入pending日志并再次核对内容，移动后读回校验。异常时尝试恢复已经移出的文件；原位置若出现新的同名内容，保留双方并标为recovery-needed，不用旧文件覆盖新文件。重启恢复可处理“移动完成但日志仍是pending”的情况，也可重复执行。

恢复发布使用独占临时副本、读回校验和不覆盖目标的原子链接。原目录若已切换到另一发行身份，停止恢复，避免混装两个版本。目录和文件名只使用已验证清单中的条目。

## 真实Electron文件系统差异

实际包首次检查发现：Electron默认fs会把app.asar看成虚拟目录。更新文件操作已统一使用physical-fs适配器，在Electron中使用original-fs，在普通Node中使用原始Node fs。模块加载仍保持Electron的ASAR支持，不全局切换noAsar。这样既能从应用包加载帮助代码，又能校验和保存app.asar本身的真实字节。

复制改用原生文件复制并进行读回校验，本机检查了Windows命名流在快照、恢复中的保留。摘要针对默认数据流；并不据此宣称完整ACL、全部元数据或故障磁盘场景已逐项验收。原生复制进行中不能由AbortSignal立即中断，取消会在该步结束后停止后续工作，不发布完成状态。

## 验证与剩余工作

- 专项覆盖未改程序文件、修改过的随包帮助、用户MD与未知资源、目录链接、受信摘要/发行身份、路径歧义、处理中的改动、失败自动恢复、并发同名冲突、pending恢复、重复恢复、换版本拒绝合并、MD优先保留和Windows命名流。
- 实际候选24包含76项程序文件清单。在隔离副本中修改一份资源、添加MD和额外资源，直接调用包内API：75项可移出程序文件暂存后恢复；修改项、原稿及设置保持。恢复后的隐藏Electron实际启动并打开MD，原字号23与琉璃主题生效。
- 同一隔离副本实际调用构建前置钩子：未改的纯程序副本可以通过，放入MD及资源改动后拒绝覆盖，原稿仍在。独立回执写入采用同步写入与原子替换。
- 真实NSIS隔离检查增加了损坏ASAR的原字节保存，避免只在普通Node或没有ASAR的fixture中通过。

完整更新仍必须保持读写进程关闭并持有贯穿更新的生命周期门禁；现有进程预检不能替代它。新版本文件安装、旧版无清单迁移、正式profile身份、路径记录、完整恢复/回滚与原发行安装器矩阵仍须继续，正式发布门槛保持未通过。内部候选24没有改变用户正在使用的文稿库，也没有执行真实模型请求。
