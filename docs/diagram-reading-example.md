# 一座桥，几种走法

**图解与旁注 · 朱墨原创示例**

一座桥把两岸接在一起，也让我们重新理解了“两岸”这个说法。图解不是把论述画成捷径。它让原来藏在句子里的连接显出形状，也提醒我们：每一条箭头都欠着一个解释。[^箭头]

```mermaid
---
title: 从相接之处，重新看见两岸
---
flowchart LR
  A[此岸的经验] --> C{如何抵达彼岸}
  B[彼岸的疑问] --> C
  C --> D[造一座桥]
  D --> E[看见新的路径]
  D --> F[承认仍有距离]
  E --> G[重新理解此岸]
  F --> G
  G -. 再出发 .-> A
```

## 相遇有它的次序

桥已经在了，并不意味着理解已经发生。一个问题抵达另一个人，要经过等待、重述和某次恰好发生的回望。[^等待]

```mermaid
sequenceDiagram
  participant A as 此岸的人
  participant B as 桥上的人
  participant C as 彼岸的人
  A->>B: 这个问题，可以带过去吗？
  B->>C: 他是这样问的……
  C-->>B: 我先说我听到了什么。
  B-->>A: 他听到的，与你所问的有些不同。
  A->>B: 那么，让我换一种说法。
  Note over A,C: 回答改变了问题，问题也改变了路。
```

## 中心并不占有一切

一张图总要在某处开始。这个起点只是我们暂时安放目光的位置；从另一侧走来，同一座桥会先呈现出完全不同的事物。

```mermaid
mindmap
  root((一座桥))
    连接
      可以相遇
      可以离开
    距离
      行走的时间
      尚未说出的经验
    材料
      石头的承重
      木头的回声
    记忆
      第一次经过
      某次没有过桥
```

## 从犹疑到行动

“决定”并不总是某个瞬间的光亮。它也可能是犹疑中一连串微小变化的名字。看清变化的条件，常常比给最终状态取名更有帮助。

```mermaid
stateDiagram-v2
  [*] --> 眺望
  眺望 --> 试探: 看见可走的路
  试探 --> 停留: 水声比想象中大
  停留 --> 试探: 重新衡量
  试探 --> 经过: 愿意承担这一步
  经过 --> 回望: 到达之后
  回望 --> [*]
```

## 比例也是一种叙述

如果把过桥的人数画出来，桥就显得像一种流量设施。但没有过桥的人、走到一半回去的人，以及只是站着听水的人，都可能不在那组数字里。

```mermaid
xychart-beta
  title "沿桥停留的几分钟（虚构示意）"
  x-axis ["出发", "桥头", "桥中", "桥尾", "彼岸"]
  y-axis "停留时间" 0 --> 12
  bar [2, 5, 11, 4, 7]
  line [2, 5, 11, 4, 7]
```

[^箭头]: 这里的箭头表示阅读时提出的联系，不自动表示因果或必然推出。如果要论证“造桥改变了此岸”，还需要说清楚改变了谁的行动、哪些生活条件，以及这个变化持续了多久。[^条件]

    ```mermaid
    flowchart TB
      A[发现一个联系] --> B[说明箭头的含义]
      B --> C{理由够充分吗}
      C -->|还不够| D[保留问题]
      C -->|在这些条件下| E[提出有限的判断]
    ```

[^条件]: 一个关系图可以把条件放进节点里，却不能代替对条件的检验。图越简洁，越需要回到那些被省略的句子。

    ```mermaid
    flowchart LR
      A[图中的结构] -. 回到 .-> B[具体的经验]
      B -. 修订 .-> A
    ```

    对于一段长度为 $s$ 的路，$t=s/v$ 只在速度恒定等假定下成立。公式和图解都需要交代自己的适用范围。[^范围]

[^范围]: “适用范围”也不是一次写完的附录。新经验可能要求我们重画箭头，或承认某个问题仍留在图外。

[^等待]: 等待改变了对话的节奏。时序图里两条消息之间的空白，不能直接换算成真实的等待时长；它首先表示前后关系。
