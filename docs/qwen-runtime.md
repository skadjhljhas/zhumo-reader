# 千问接入与实际句法运行 · 候选19

阅读模型与句法模型均可使用千问平台的 `qwen3.8-flash`。本次按用户提供的平台文档，将兼容接口配置为 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`，两套模型保留各自的系统提示词、32k最大输出与不思考设置。密钥由系统加密保存，不进入网页或版本库。

## 接口参数

Qwen3使用顶层 `enable_thinking`，关闭时为false；不是DeepSeek的 `thinking.type`。Qwen3.8的推理力度使用low、medium、xhigh，界面中的最大映射为xhigh；原来的high也按服务商约定映射到最高档。关闭思考时不附带推理力度。没有同时发送thinking_budget与reasoning_effort。

依据：[平台首次调用文档](https://platform.qianwenai.com/docs/developer-guides/getting-started/first-api-call)、[Qwen3.8-Flash说明](https://platform.qianwenai.com/docs/developer-guides/getting-started/latest-model)、[思考模式](https://platform.qianwenai.com/docs/developer-guides/text-generation/thinking)。

## 不再默默没有标注

本轮核对了实际运行的候选18、已开启的自动句法，以及丰沛光效设置。没有把现场问题直接归因于用户打开错版本或关闭了开关。

程序修正了几个会造成无反馈的路径：

- 阅读窗口是否在前台由主进程的原生窗口状态判断。窗口处于前台、但DOM没有焦点时仍可准入；最小化或切到别的窗口暂停新分析。浏览器示意保留浏览器焦点判断。
- 句段按实际可见文字面积达到70%准入，仍要求停留十秒；不再要求每一个字形矩形都完全落在视口里。覆盖面板按实际遮挡扣除。
- 某个句段的结构解析失败只使该句段失败，后续合格句段继续。接口授权、网络或限流错误仍暂停队列，避免无限自动重试。
- JSON行可以有合法的多行排版或外层代码围栏。程序等待完整对象后验证，不补括号、不猜失效锚点、不执行返回的代码。
- 模型配置刷新会重新读取磁盘；凭据调用检查配置版本，过期的设置窗口不能覆盖另一个进程更新后的配置。

这些修复针对已确认存在的代码路径，不等同于声称已经读到了用户先前每一次失败的接口内容。

## 运行状态

配置句法模型后，底栏在首次请求之前也会显示当前状态。点击可看到：使用的模型、可见句段、达到停留条件的句段、实际绘制标注、收到的成分和关系，以及未完成句段的原因。

细读栏中的「分析当前可见句段」是显式立即分析入口，不改变默认随阅读自动准入的流程。「刷新模型配置」读取最新的磁盘配置；原有选区注释、自动解释、自动复制三个开关保持独立。

## 验证口径

使用一次固定JSON回传消息检查真实千问接口，没有发送用户文稿，也没有评测模型的语言能力。返回HTTP200，接口关闭思考生效，输出解析为两个成分和一条关系。该公开固定回传结果随后通过本机服务，在正式主进程/IPC/渲染链路中回放并绘制。

专项检查还覆盖：原生窗口有焦点而DOM无焦点时的自动准入；前一个句段失效后后一个仍可显影；配置外部更新与过期保存保护；千问思考参数；多行及围栏格式的增量解析。窗口检查均使用隔离资料的隐藏实例。

真实平台的联通检查、真实返回的本地回放、固定数据的工程回归分别记录，不把其中任何一种当作真实模型能力评测。
