# 全文标注与三个光学通道

左侧「字」提供跟随阅读、全文标注两个选项。全文模式会关闭跟随模式的调度；主进程也取消相反模式的后台任务，避免切换时的异步竞态。切换先持久化设置，再启动新请求。两种模式使用同一个 syntax 模型配置与密钥，分别保存 `systemPrompt` 和 `documentSystemPrompt`。

全文模式从完整解析结果建立正文、标题和注释的文本块索引，不需要先滚动或挂载它们。请求同时带完整 Markdown 和 `blocks: [{id,text}]`。模型可据全文建立概念、论证与声音的跨段联系，再选出具体表达；微观语法、辖域、模态和指称关系仍可通过同一组标注手段表达。

```jsonl
{"type":"begin","version":4}
{"type":"mark","blockId":"b-0-2","quote":"自由","occurrence":1,"textColor":"#704668","glowColor":"#d8c49b","radiance":0.55}
{"type":"done","summary":"概念在首尾的复现构成一条阅读线索。"}
```

`blockId` 必须属于本次文稿，`quote` 在该块内逐字定位，`occurrence` 从 1 开始。字体和荧光分别使用独立色号；`radiance` 是可选的第三维，不改变两个色号的选择。跨段联系分成相关位置上的多条标注，不拼接不连续引文。普通字形以 CSS Highlights 绘制；公式作为完整原子对象接受外部光效，避免染色透明排版占位符。

每条完整记录即刻验证、显影；未到视口的结果留在本地状态中，显示该段时可以直接呈现。换文稿、改提示词/模型/配色会改变任务身份；渲染身份也包含文稿世代，避免快速切换同位置文字时复用旧标签。完整缓存包含模式、实际使用的提示词、原文、文本索引与阅读配色。改跟随提示词不会使未改变的全文提示词缓存失效，反之亦然。

默认参数沿用模型：输出长度使用省略参数，思考模式和强度也不强行指定。默认上下文发送完整文稿；模型的实际容量由服务商判断，应用不偷偷截成 200k。若接口强制要求输出上限，可选择自定义或使用请求体代码。存储层以兼容标志表达默认选项，保留旧版可读的数值和上下文字段；默认选项重启后仍有效，密钥不重写。

全文输入仍有应用接收边界：Markdown 16 MiB、索引至多 20,000 个块和 8 Mi 个字符、输出至多 8,192 条 mark。它们是防止无界内存使用的边界，不是模型 token 上限；超限拒绝而非截断。每批最多 48 条。坏记录与后续有效记录隔离，受损的整次结果不会作为完整缓存保存。

光华通过全局光层向段落外扩散，不受单个段落裁切。HDR 采用 `rgba16float` 和扩展亮度；普通荧光继续保留在文字宿主中随原文滚动。光源的位置、颜色与 GPU 缓冲复用，稳定阅读时不逐帧重测文字。SDR 也使用 GPU 光晕管线，以 `rgba8unorm` 输出标准亮度；不支持 GPU 时保留轻量回退。

验证使用固定本机接口，未测试真实模型能力：字色截图、标题定位、HDR 光层读回、屏外段落、原文不变、任务互斥、重启缓存和两份提示词独立保存均通过。读回得到的白底合成值约 1.59，是渲染值而非显示器亮度测量。证据见 `work/whole52-final-desktop.log`、`work/skylight53-render-checks.log`、`work/whole52/emission.json`。
