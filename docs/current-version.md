# 当前版本指针

这是一项供更新协调者使用的磁盘协议。它负责将“当前运行哪个版本”发布成一个完整的小文件；不是完整安装器，也不认证发行者签名。

安装根必须已经存在，是绝对、非盘根的真实目录。版本只能存放在 `.zhumo/versions/<releaseId>`，`releaseId` 和 `transactionId` 使用规范小写 UUID。指针位于 `.zhumo/current.json`，只允许以下字段：

```json
{
  "version": 1,
  "releaseId": "b6a8f30a-5f90-4fe9-9a80-9a7c1aefcd2d",
  "transactionId": "15e8ae23-a848-427f-8aee-ec1902daa78a",
  "manifestSha256": "<64 位小写 SHA-256>",
  "appId": "<发行清单中的 appId>",
  "appVersion": "<发行清单中的 appVersion>",
  "executable": "ZhuMo.exe",
  "profile": "D:/朱墨数据/配置"
}
```

`profile` 是可选字段，旧版七字段指针仍兼容。有此字段时，必须是绝对、非盘根且不含 NUL、CR 或 LF 的目录路径，并在读取、解析和恢复时原样保留。配置目录允许位于安装根外；它不参与可执行文件定位，此模块只验证目录语法，不打开或创建配置目录。启动器优先使用用户显式的 `ZHUMO_USER_DATA`，否则使用指针中的 `profile`；主进程继续执行正常的配置目录初始化与校验。

`readCurrentVersion(installRoot)` 返回 `{pointer, bytes}`，其中 `bytes` 保留磁盘 UTF-8 的原始换行与空格，以便做精确比较。只有指针真正不存在时返回 `null`；这也包括暂存版本已建立而首次指针尚未发布的阶段。安装根缺失、损坏 JSON、无效 UTF-8、权限错误、链接、非普通文件不能转成空值。只读函数不创建或修复目录。

`resolveCurrentVersion(installRoot)` 在没有指针时抛错。成功时返回 `{directory, pointer, manifestBytes}`，`manifestBytes` 是实际清单文件的 `Buffer`。它检查安装根到版本目录的全部祖先，拒绝符号链接、junction、Windows 重解析点及偏离规范路径的别名；要求目录实际保持在安装根中。清单必须通过 `readProgramManifest` 的摘要及结构校验，且 `appId`、`appVersion`、`executable` 与指针逐字匹配。入口文件必须实际存在且路径安全。元数据和入口不能是硬链接。

这个解析检查不替代新版本逐文件核验。更新协调者必须先调用发行暂存模块的完整验证，验证所有程序文件，然后才发布指针。不能因为清单自身通过校验，就声称包中每个文件都已验证。

`publishCurrentVersion(installRoot, next, expectedBytes)` 要求调用者已持有覆盖安装根的更新准入，并持续持有到发布与后续事务记录处理结束。跨进程写入依赖这项准入；函数另行串行化同一进程内对同一安装根的调用。首次发布必须显式传 `null`，升级及回滚必须传此前读取的原始 `bytes`，不能用重新序列化的相同对象替代。

发布会先验证当前原始字节及目标清单身份，再用同目录、独占创建的随机临时文件写入完整指针，执行文件 `fsync`，读回校验；随后重新检查目标及原始指针字节，最后用原子 `rename` 发布。字节比较不符、临时写入失败或重命名失败时不替换旧指针。临时文件清理仅针对本次已确认身份的文件。没有任何删除旧版本目录或用户文稿的操作；回滚是持新事务 ID、明确提供预期旧字节的另一次指针发布。

原子发布成功后函数不再执行可能向调用者报告“发布失败”的磁盘操作。操作系统崩溃及断电后的最终事务判断，仍由持久化事务记录和协调者恢复流程负责。文件 `fsync` 加原子重命名不等于对任意硬件、文件系统或不遵守准入的外部写入者作出保证。

`restoreCurrentVersion(installRoot, previousBytes, expectedBytes)` 用于协调者失败或恢复路径，同样要求持有安装根准入，并与发布共享同进程串行锁。`expectedBytes` 必须是本次已发布的完整原始指针，当前磁盘字节不同则拒绝恢复。

- `previousBytes` 为字符串：先校验原有指针、版本路径及清单身份，再通过同样的完整临时写入、`fsync`、读回与原子替换，逐字恢复原有 JSON 的空格、CRLF 等格式。不会把原始记录重新序列化。
- `previousBytes` 为 `null`：恢复首次切换前没有 `current.json` 的状态。当前指针整体原子改名为同目录 `current.aborted.<UUID>.json`，留下完整回滚记录；不调用删除。归档名若已有文件、目录或链接就拒绝，不覆盖历史记录。源字节和目标不存在状态在移动前再次核对。

两种恢复都保留全部版本目录及文稿。恢复后没有可能把成功切换报告成失败的额外磁盘操作。原有清单不安全、当前指针已变、重命名失败时保留当时的当前指针，由协调者保持准入并决定后续恢复步骤。

Windows 重解析点补充检查使用隐藏 PowerShell 子进程，只读取路径属性；查询失败时拒绝切换。常规单元测试不启动 Electron，不发送模型请求。磁盘测试覆盖首次发布、升级、回滚、并发同预期冲突、原始字节不同、坏指针、清单身份不符、链接祖先和目标、重命名失败与临时文件写入后指针改变。
