# 产品身份与阅读资料

2.0 的产品身份由包内 `zhumoChannel` 指定，不再从版本字符串推测。AI、潮光和普通预览继续使用各自的资料目录。正式 2.0 使用 `com.zhumo.reader.v2`，与原版的 `com.zhumo.reader` 并存；候选的 rc 版本号不会改变资料位置。

## 第一次继续阅读

明确的受管安装绑定或 `ZHUMO_USER_DATA` 优先。没有这类绑定时，正式产品查找原版、AI 预览、2.0 预览、潮光预览及 2.0 的已有资料。

- 只有一套有阅读资料的目录：整套沿用。
- 有多套：在第一次打开时选择继续使用的一套，也可以从新资料开始。
- 没有旧资料：使用新的 `ZhuMo-2.0` 目录。

选择窗口由小型 Windows 原生程序显示，没有 Chromium 资料目录；选择发生在阅读进程的 Electron ready 之前。它只显示资料名称和位置，不读取密钥。静默安装遇到尚未选择的多套资料时退出并说明原因，不弹出选择窗口。

选择记录单独位于 `%APPDATA%/ZhuMo-profile-bindings/com.zhumo.reader.v2.json`。它包含原目录的实际路径和文件系统身份。记录损坏、目录失联或被替换时停止打开，不改用同名空目录。取消选择不创建新的阅读资料。

这是整套沿用，不是字段合并。`Local State`、加密模型配置、Chromium Local Storage/IndexedDB、导入字体、回声记录、未命名草稿、阅读进度等都留在选定目录中；其它资料目录不改动。不同平台的系统加密机制不同，本轮跨产品实测范围是 Windows 本机。

## 安装与恢复

已有安装的 current 指针、卸载后保留的 profile 记录优先于全局选择。首次选择在安装开始修改之前保存，因此第一份 current 尚未发布时的重试也能找到已经选定的资料位置。更新事务继续保存整份 profile 与文稿库。

新产品默认使用独立的 `Programs/朱墨 2` 安装位置和 `朱墨 2.0` 系统入口。原版 NSIS 的卸载登记不被覆盖，旧卸载器不被执行。原版 1.1.x 有时只有带引号的 `UninstallString`，没有 `InstallLocation`；该路径仅用于识别旧安装目录。新版拒绝将程序装进旧卸载器会递归处理的目录或与它重叠的目录。

文件“打开方式”使用独立的 `ZhuMo2.Assoc`，支持 `.md`、`.markdown`、`.epub`；旧版的关联项保留。它不替用户更改 Windows 默认应用。
