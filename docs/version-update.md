# 本地版本切换、回滚与启动

新流程不在混有用户文稿的旧目录上覆盖整套程序。安装根下 `.zhumo/versions/<UUID>` 存放独立版本，`.zhumo/current.json` 是当前启动入口。旧程序、文稿、图片与配置根始终保留，回滚只恢复入口，不把旧备份盖回用户的新内容。

## 正常更新

`installVersion` 接收明确的安装根、资料目录、受信发行清单摘要、待复制程序和原指针字节。它校验新发行、取得安装根与资料的更新准入、用独立运行时持有原生资料锁，再建立完整保存点。已绑定的外部文稿库自动加入保存范围；失联绑定明确失败。

全部文件复制到全新版本目录，并在源与目的完整读回核验；此时仍未切换当前版本。原有文件再检查通过后，先发布持久mutating状态，再原子切换current。指针携带这次保护的profile，避免更新A设置却启动B设置。验证入口、发行与原文件后才完成事务并释放原生锁。

`version-update-runner.js` 是独立Node模式帮助入口；安装器应先准备可信新运行时和本地计划，再启动它。计划不从Markdown或模型输出中读取。阅读进程仍打开时，流程拒绝开始，不强杀窗口。

## 启动链

稳定快捷方式可指向一份保留的运行时，并使用 `--zhumo-launch-current <安装根> -- <可选文稿路径>`。启动器自身不创建阅读窗口或打开真实profile；它核对current、已知程序文件及清单，再启动当前版本。参数通过argv数组传递，支持中文、空格和符号，不经shell。

显式ZHUMO_USER_DATA优先，否则使用指针保存的profile。新阅读进程确认自己属于受管UUID目录后，把稳定安装根加入启动准入；首次文稿位置以该根为基础，既有绑定优先。

暂存包严格拒绝额外文件；安装后启动仅验证清单所列程序，不枚举或执行用户新增的MD、图片或链接。新增文稿不会被误判为坏程序，也不会被清理掉。

## 中断与恢复

事务目录保存原始指针字节、来源清单、快照和守护位置。切换后失败且仍能证实持锁时，自动恢复原始指针；首次安装失败则归档新指针，使current恢复不存在。冲突保留双方，不覆盖后来改变的入口。

recoverVersionUpdate需要明确的安装、profile、协调目录和操作。恢复进程按原token接管同一事务全部死亡的写入者，再认证重连原守护；不能只因PID存在就宣称持锁。守护消失时，新守护必须实际取得原生锁。恢复入口不恢复旧文稿覆盖物，用户之后写的内容保留。

恢复者连续崩溃，以及完成阶段只标完部分旧token后中断，也可从持久原token找回同一事务。存活写入者、其他事务或不同资源范围仍拒绝接管。

## 证据与边界

磁盘测试覆盖独立安装、绑定库、首次/后续回滚、保留用户新写的文稿、失联库和显式恢复。真实隐藏桌面流程以候选27隔离副本为旧程序，验证升级、字号/主题/加密配置、真实启动器转交中文文稿，以及更新器发布后退出再由新进程继续提交或回滚。检查原文件字节、实际版本和打开行为，未调用模型。

这是已接通的本地同产品更新与启动流程。**正式NSIS用户入口、稳定版与AI预览身份选择/迁移、原版安装器矩阵和最终签名仍未完成。** 不把此API称为已发布的自动更新服务，也不把内容校验扩展成全部NTFS元数据或硬件故障的绝对保证。
