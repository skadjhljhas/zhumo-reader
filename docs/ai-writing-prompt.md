# 朱墨 2.0 · 给 AI 的写作环境

在朱墨左侧点击「AI 注释写作协议」，可以复制完整协议或纯渲染约定，并直接打开一篇带多入口与三层注释的原创范例。

## 让 AI 学会写注释

把 [注释写作协议](ai-annotation-protocol.md) 交给写作工具，然后提供自己的材料与具体任务。协议覆盖正文与旁注的分工、注释增加的实际内容、进入与返回、注内注、多入口复用、命名自由、来源责任和 Markdown 结构。

协议允许有充分展开的长注，也允许没有注释；不规定固定类别、密度和文风。对已有文本补注时，以用户授权的修改范围为准。

协议包含两组具体对照：一组辨认论证中尚未区分的条件，一组从文学措辞出发保留未定的意义。它同时说明“只允许补注”时如何处理原文的前提缺口，以及怎样比较同词异义的两处文本；复制完整协议时，这些例子会一并带上。

这里的“学会”需要通过实际作品检验。随附的 [原创范例](annotation-example.md) 可以在朱墨中沿注释路径阅读；[质量验收与验证任务](annotation-review.md) 用于检查模型实际产出的内容。结构解析通过不能代替内容判断，也没有被宣称为跨模型评测成绩。

## 只说明渲染行为

如果写作者已有自己的写作方法，只需要知道文件格式，复制 [纯渲染约定](renderer-contract.md)。它说明真实支持的语法、层级、命名、公式、图片、链接与文件编码，不包含写作风格指令。

## 使用顺序

1. 提供所需的协议或渲染约定。
2. 提供材料、目标读者、任务与允许修改的范围。
3. 让 AI 交付 Markdown，在朱墨中检查正文、旁注和返回路径。
4. 对具体问题提出修改要求，例如某条注缺少独立观点、某条子注没有必要、某处来源未核实。

让反馈对应实际文字与阅读体验，逐步改进作品和协议。
