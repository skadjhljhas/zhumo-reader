# 琉璃 HDR 的显示节奏

## 字缘反光与静谧滚动（2026-09-10）

反光已改为字形透明度蒙版与 GPU 焦散/柔化绘制，取消了曾造成明显合成开销的全字 CSS 阴影与墨色变化。普通滚动复用纹理并更新坐标，窗口/字号/字体变化才重建；静谧模式由交互事件触发重绘，冻结光的时间而非冻结文字位置。中文两端对齐按实际逐字位置取样，嵌套视口裁切也作用于光层。

当前 4K 隐藏共享纹理场景（10 路本机固定响应、80 处标注、3 处光华）：HDR 显影 235.2 fps、滚动 230.5 fps；SDR 显影 231.8 fps、滚动 232.3 fps。四个阶段 p95 均约 4.3 ms，各有 1–2 个超过 16.7 ms 的长帧。日志 `work/hdr-perf/annotations-reflection62-hdr.json` 与 `annotations-reflection62-sdr.json`。它们仍是后台吞吐数据，不能据此宣布物理显示全程稳定 240 Hz。

下列段落保留此前性能演进记录；当前美术结构已是两束柔光与一层较宽的折射微光，不再采用四束加四层条纹。效果方案见 [天光与字缘反光](skylight-and-ink.md)。

补齐图片/旁注尺寸失效、字体特性与设备重建后，同场景 HDR 显影 230.4 fps、滚动 234.0 fps；SDR 显影 234.6 fps、滚动 234.5 fps，p95 仍约 4.3 ms。数据：`annotations-reflection63-hdr.json`、`annotations-reflection63-sdr.json`。HDR 曝光随后移除过高的启亮门槛，直接按光场能量连续增亮；实际浮点读回峰值 1.236（`work/reflection63-fonts-replay.log`），SDR / HDR 的设备重建均有隔离检查。物理屏幕实测仍不由这些结果替代。

## 当前补充：标准亮度也交给 GPU

天光和全文标注接入后，补测发现 SDR 的旧 SVG 路径仍会在密集标注时卡顿。现已将普通荧光和光华统一到 GPU 管线：SDR 为 `rgba8unorm`，HDR 为 `rgba16float`，分别使用标准与扩展亮度。原 SVG 保留回退和定位元数据；GPU 绘制时不再更新它的运动/透明度变量。图形管线在阅读空间开启时预热，减少首批标注抵达时的初始化工作。

同一 4K 隐藏纹理场景（80 处标注、3 处光华），SDR 原路径显影 42.6 fps、滚动 29.2 fps；改后约 206 fps、229 fps，p95 约 4.3 ms。数据：`work/hdr-perf/annotations-sdr55.json`、`annotations-sdr56-final.json`。字体、滚动对齐、HDR 回退和全文缓存检查仍通过。数值表示后台渲染吞吐，不是前台扫描帧率。

完成阅读空间预热后，同样场景测得显影 234.2 fps、滚动 234.8 fps，p95 约 4.3 ms，两个阶段各有 1 个超过 16.7 ms 的长帧。数据：`work/hdr-perf/annotations-sdr56-warm.json`。候选 56 的可执行文件另通过全文标注、独立提示词、模型默认参数、屏外结果与重启缓存流程。

目标是按实际显示器刷新率呈现光效，保留屏幕原生像素尺寸、四层噪声、四束散射光与四层折射纹理。以本机 240 Hz 为例，每帧预算约 4.17 ms。动画帧时间、GPU 队列等待和真实显示器刷新率分别记录，不用隐藏窗口的结果冒充前台帧率。

## 渲染路径

- 琉璃背景直接由 WebGPU 输出 `rgba16float` 扩展亮度。背景光场与曝光合并为同一次 GPU 绘制，取消原来的整屏 WebGL → WebGPU 转交。四层噪声保留，格点随机值由本次阅读会话共享的 GPU 纹理提供；SDR 与 HDR 使用相同纹理。只与本帧有关的三角函数放到顶点阶段计算。
- 文字荧光使用 GPU 实例绘制。颜色转换只在颜色数据更新时计算，GPU 负责渐变形状、显影和外围运动。字体颜色仍由原生 CSS Highlights 呈现；渐变变量限制在相关文字宿主中。
- HDR 光层共用设备与管线，每个显示帧集中提交。静止的光层保留最后结果，视窗外的光层暂停。调度器避免生产者在 rAF 里排下一帧导致隔帧提交的问题。
- 回声保留完整画布坐标，仅传输新旧光晕覆盖的更新区域，清除旧位置也包含在区域中；不改变正文与荧光的滚动关系。
- 标注画布尺寸只有真正改变时才更新；缓冲区按容量复用。不因普通滚动、计时文字或无关 UI 的变化重新测量整篇文章。原生坐标随段落和注释卡一起滚动。
- HDR 文本荧光由 GPU 单独呈现，SDR 的 SVG 光晕子树在 HDR 下停止布局和绘制。滚动余光直接更新 GPU uniforms，不再修改隐藏 SVG 的 CSS 变量。原生字色继续柔缓变化，外部光效的显影与颜色层次由 GPU 完成。
- CSS Highlights 规则限定到相关段落；范围不变时保留同一个 Highlight 实例。光层几何按段落一次读取，之后统一修改样式。彩色标注的父组件保持数据引用稳定，滚动仅为旧式关系图更新屏幕坐标。
- HDR 开启时预编译文字荧光管线，减少首次标注抵达时的初始化工作。
- 颜色规则通过 CSSOM 增量维护，流式新增或删除只处理对应规则；已存在的范围、规则和 GPU 缓冲保持驻留。HDR 与 SDR 切换时更新相应声明，PDF 快照仍从 CSSOM 读取完整样式。

PDF 导出前会要求背景生成当前时刻的 SDR 定格，供静态主题导出使用。

## 已有证据

43 的真实前台记录确认了性能瓶颈仍存在：标注生成或交互时帧率明显下跌，GPU 队列等待可达到数十毫秒。该记录不作为优化完成证明。

45 已确认使用 NVIDIA GPU，并在主显示器 240 Hz、200% 缩放、最大化窗口中记录到最高 240 fps；119 个有效前台样本的帧率中位数为 195.9，最低为 45.8。它仍未达到持续匹配刷新率的目标。其背景已累计直接绘制 21,519 次，来源画布复制仅 1 次，证明主要背景搬运已消除。日志：`work/hdr-perf/reader45-onscreen.jsonl`。这里的 fps 是应用提交节奏，不等同于独立硬件扫描输出采样；PresentMon 未能在本次普通权限环境启动。

后续修改已通过原生 HDR 浮点输出、滚动贴合、字体重启恢复、不重复设置相同画布尺寸，以及回声局部传输的检查。回声验证使用独立资料和本机固定响应，平均每次复制区域小于视窗面积的 20%。源测试日志为 `work/hdr46-desktop.log`；前台复测继续进行。

### 大量标注的重复测试（候选 50）

使用同一篇固定文稿、10 条同时保持连接的本机 SSE 流、80 处逐批返回的颜色标注，在 3840×2160 的共享 GPU 纹理上比较。测试运行在隐藏窗口，设置 240 Hz 调度；这些结果表明渲染吞吐量，不代表物理显示器的扫描帧率。

| 场景 | 修改前 fps | 修改后 fps | 修改后 p95 帧间隔 |
| --- | ---: | ---: | ---: |
| 无标注背景 | 239.7 | 239.4 | 4.2 ms |
| 流式标注与柔缓显影 | 67.6 | 230.4 | 4.3 ms |
| 标注完成后静止阅读 | 221.7 | 240.0 | 4.2 ms |
| 滚动已标注正文 | 27.6 | 234.3 | 4.3 ms |

显影阶段 5 秒内的样式重算时间从 3.208 秒降到 0.902 秒；滚动阶段 4 秒内从 2.708 秒降到 0.037 秒。保留 GPU 原生像素尺寸、色彩层次、2.6 秒显影与滚动余光。对应原始数据：`work/hdr-perf/annotations-baseline49.json`、`annotations-gpu49.json`；最后一份包含候选 50 的绘制逻辑，但尚未加入管线预编译。该对照仍有个别长帧，不能据此声称所有场景都稳定 240 fps。

软件验证覆盖 10 个请求占满时第 11 个等待、空位补入、坏流继续显影、10 个完整结果重启缓存，以及 1–15 秒设置持久化。真实模型能力没有参与上述测试。

候选 50 的真实前台 HDR 测量得到 20 个有效样本，主显示器 240 Hz、200% 缩放、NVIDIA GPU，帧率中位数 225.45、最低 177.2、最高 240。光晕实际累计绘制 31,069 次，因此包含标注显现期间的工作。日志：`work/hdr-perf/reader50-onscreen.jsonl`。前台改善已得到证据，仍存在未达到刷新率的时刻。
