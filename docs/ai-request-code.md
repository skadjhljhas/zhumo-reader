# 简易模式与代码模式

阅读模型和句法模型分别保存配置，每套都可选择简易模式或代码模式。简易模式使用常见表单，保留的代码不运行。代码模式直接编辑 JavaScript 请求体，模型名可完全写在代码里；已有连接设置可折叠，系统提示词与阅读上下文仍由软件提供。

例如，Chat Completions 请求体可以这样写：

```javascript
return {
  model: "你的模型 ID",
  messages: request.body.messages,
  max_tokens: 32768,
  stream: true,
  temperature: 0.6
};
```

Messages 协议还应保留 `system: request.body.system`。旧代码仍可修改 `request.body` 并 `return request`，也可用完整请求形式修改请求头与同源路径。为兼容旧代码，`request.body` 提供基础设置生成的请求；直接返回完整请求体可以替换其参数。

**Qwen 不再有独立思考长度按钮，也不自动发送 thinking_budget。** 服务商专属字段由用户在代码里明确配置；原来保存的专属开关被忽略，其他设置和密钥保留。

切换模式保留各自内容。简易模式将非活动代码独立保存，活动requestCode留空，避免旧阅读器误执行它；新版本重开时恢复编辑内容。只有代码模式会编译和执行代码，语法错误会明确阻止保存，不偷偷切换模式。

`{{API_KEY}}` 是请求头的密钥占位符，实际密钥由主进程在构造完成后注入，不传入代码。不要把真实密钥写进代码文本。仅用户显式保存的请求代码会执行；文章、注释、模型思考和正式输出均不作为代码执行。

代码在可取消的临时工作线程运行，有执行时限和内存限额；只提供 JSON 输入，不提供文件、网络或模块 API。接口可改为同源的其他路径，更换服务商则更改 API 地址并重新配置密钥。保留 `body.stream = true`。响应解码仍使用所选 Chat Completions/ Messages 协议，本功能不宣称支持任意响应协议或完整 Node.js 插件。

有效模式及活动代码参与缓存键，编辑非活动代码不会改变简易请求的内容缓存。建议代码仅由输入决定，不依赖随机数或时间，因为相同配置与句段会复用已验证的结果。

## 思考与标注是两个交付阶段

服务商的 `reasoning_content` 用于展示思考，不能用作正文结构。正式 `content` 中完整、经过逐字锚点与关系校验的 patch 才参与绘制。状态明确区分：等待响应、只有思考、正式结构抵达但第一批尚未完整、已有结构待定位、关系显影、完成但没有可定位成分、失败。

连接测试使用所选模式和真实参数，仅将消息换成不含文稿的短内容；不再强制关闭思考。

HTTP 错误保留状态码、已知错误类型和涉及的参数名；不展示可能回显密钥或文稿的任意响应正文。

具体路由的参数支持以服务商为准，代码模式让用户直接控制这些字段，不再为每个专属参数添加界面按钮。

## 验证

检查覆盖模式切换/重开、活动与非活动代码隔离、直接返回请求体、不填写简易模型名也能自动分析、旧代码迁移、密钥保留与预算字段移除。窗口验证使用本地固定响应，不调用用户的付费模型。
