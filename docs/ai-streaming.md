# 随阅读逐批显影 · 候选16

## 最大输出与思考

两套模型的预设最大输出都是32768 tokens。旧版本未带思考设置、且仍使用8192默认值的配置会迁移到32768；以后用户明确保存的长度原样保留。保存的密钥密文不因迁移被替换。内置旧句法提示词升级到v3，自定义提示词保留，应用追加同一流式输出契约。

全局「模型、密钥与系统提示词」中，两套模型各有思考模式与思考强度。DeepSeek Chat Completions 使用 `thinking.type` 和 `reasoning_effort`，支持low/high/max；保留服务商默认时不发送相应字段。关闭思考时不再发送强度参数。Messages适配使用 `output_config.effort`；DeepSeek不使用手动budget。其他支持手动思考的Messages模型可设置预算，并要求预算小于最大输出；支持adaptive的新版Claude可选择自适应模式。参数支持范围以所选模型为准。[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[DeepSeek Messages适配](https://api-docs.deepseek.com/guides/anthropic_api/)、[Claude手动与自适应思考](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)。

接口实际返回的 `reasoning_content` / `thinking_delta` 通过独立事件抵达界面。自动解释浮层与细读栏在生成过程中即可展开查看；用户向上翻看时不会被强拉回底部。思考内容使用纯文本显示，不参与句法解析，也不伪造尚未收到的思考。结果缓存保存完成的答案，不假装重放缓存中不存在的思考流。

思考模式可能先生成思考、再开始正式答案。程序能及时显示已返回的思考，但不能在服务商尚未交付结构时捏造关系。追求更早显影时可以给句法模型选择低思考强度或关闭思考；32k是输出上限，不是必须生成的长度。

## 自动阅读的准入

「阅读设置 → 句法之光 → 随阅读自动分析句法」控制自动请求与覆盖层。新版本默认开启，只有句法模型已配置时才会请求；三个选区动作开关仍各自独立。

- 正文句段至少70%的文字排版面积连续可见十秒后进入队列。计时使用单调时间；快速滚过、不可见、被弹窗遮挡、切到其他窗口的时间不计入。没有任何可见倒计时。短段落优先整体分析，避免割断相邻句子的照应。
- 拖选释放与键盘完成选区表示更明确的意图，选区优先开始。不会因点击工具栏时仍保留原生选区而重复请求。原生选区保留不会再永久关闭光效层；实际拖选时暂时隐藏覆盖层。
- 句法同时至多一个请求；后台准入每次检查当前可见范围，未到资格的内容不会被遍历发送。滚走或失焦后暂停新请求，已经准入的慢请求可以完成进入缓存，避免反复丢弃已经生成的思考。新主动选区可抢先；改文稿、换书、进入编辑或关闭自动句法会取消相关旧工作。
- 可见短段落上限1200字符；过长或不能充分可见的段落按句子与从句规划约480字符的稳定阅读窗口。窗口不随滚动位置截取，前后文仍用于判断整句关系。公式、行内代码不再让整段失去资格：以原文投影传入，并附类型边界。公式只作一个不可分的可视区域，避免重复计算KaTeX内部字形和辅助文字；纯代码、独立公式与图表不作为自动自然语言目标。明确选区上限12000字符；极长原子区域也受此硬上限约束。当前自动扫描正文，主动选区支持正文与旁注。
- 句法默认使用选段前后各最多100k字符的源文语境，也可改为仅句段。原来使用内置提示词的旧句法默认配置同步升级上下文；自定义配置保留。计数是字符，不等于tokens。上下文按原文地址验证，不能靠第一次同名句子猜位置。
- 本会话最多保留96个句段条目；完成结果还会用系统保护后落入本地缓存。键包含文本、精确上下文、模型、地址、提示词、输出契约、混排类型与窗口边界、思考参数和输出上限。设置、文稿变化不会误用旧结果。错误或被截断的结果不进入完成缓存；错误会在状态栏和细读栏显示，等待用户处理，不自动连续重试。

## 提示词与软件的流式契约

v3使用NDJSON，每个完整JSON行是一个事务：

1. `begin` 声明流版本3。
2. `patch` 携带少量完整units和relations，以稳定ID添加或原位更新；已有未更新对象保持原样。一个patch通常2–6单位、1–4关系。
3. `done` 提交最终摘要并结束。未收到done的流仍是部分结果。

每个patch先验证原文锚点、出现序号、Unicode边界、单位、关系端点和候选依赖，再整体应用。不解析半行JSON，不用正则修补缺失括号，不从思考文本猜测标签。不能对应原文的后续批次会停止应用，前面已经验证的关系保留。旧v1/v2完整JSON继续兼容，但只有v3能逐批交付。

互斥读法与分支对象在同一批中原子提交；正文一次呈现一种读法，细读栏可比较，隐含单位始终没有虚构的字形。模型只描述语言关系，颜色、透明度和流动由应用控制。程序不把模型分析显示为经过校准的正确率。

## 显影

新关系从无光开始，约3.6秒柔缓出现。已有关系不因新批次抵达而重新启动；相关词的光有共同相位，其他关系使用不同相位。光只覆盖真实排版范围，随滚动和重排重新测量，不插入、替换或移动正文字符。琉璃偏冷白折光，潮光偏月白与暖色反射。文本墨色保持不变，新增存在感集中于字底与行间。

正文底部的「句法正在思考 / 正在显影」入口可查看当前句子、接口思考流、关系依据及错误，不自动弹出独立对话框。

## 验证范围

`tests/syntax-stream.test.ts` 验证任意字符切分、第一批提前提交、后续非法批次回滚、稳定ID更新、未完成不缓存与可见时长。传输与配置测试覆盖思考内容分流、参数映射、旧默认升级和密文保留。`tests/e2e/syntax-stream.spec.ts` 用本机固定SSE服务经过真实主进程、IPC、Vue和SVG；含重启缓存复用、原生选区、十秒准入、隐藏时间、错误保留、自动解释与输入并存。

所有窗口检查使用隔离用户资料的隐藏实例，未调用用户的DeepSeek API，未评测模型能力。浏览器 `aiDemo=stream` 是另行标记的固定分批示意，不读取桌面密钥，不冒充模型分析。

## 候选21：混排与长句

`tests/e2e/mixed-syntax.spec.ts` 使用隐藏Electron和本机固定响应，验证混排实际准入、分式的唯一可视区域、公式整体选取、长句窗口的上下文与显影，以及原文件BOM/CRLF字节保留。`tests/syntax-passages.test.ts` 检查稳定窗口、保护区域、Unicode字素边界；传输/缓存检查确保混排类型和窗口边界可被模型读取且不会误命中旧结果。没有调用真实模型或用固定响应评测模型能力。

窗口外的论元或先行项目前只能由上下文及无锚点单位表达；不同窗口的关系图尚未自动合并。公式内部局部源码不绘制猜测光效；公式整体可参与周围自然语言的关系。

候选23补充按实际排版高度的惰性细分：旧窗口物理上放不进可视区且未满足准入时，使用稳定子窗口；原句边界、混排保护和十秒条件保持。已有父结果可覆盖缩窄后的子窗口，避免重复请求。普通屏幕边缘的短句不会因此切碎。超长不可拆原子区域、极端排版仍有边界，不能声称任意排版都已验证。关闭设置退场后恢复光层、跨行光路与具体证据见[句法23](syntax-viewport-optics.md)。
