# AI 细读与句法之光

朱墨允许读者分别连接阅读模型和句法模型。两套模型可以来自不同服务商，也可以指向本机服务；各自拥有 API 地址、模型名、密钥、可编辑系统提示词和输出长度设置。应用不自带 API 额度。

## 使用

1. 从左侧的“AI 细读与句法之光”或阅读设置中的“模型、密钥与系统提示词”进入配置。
2. 在“阅读”页填写擅长理解的模型；在“句法”页填写第二个模型。填服务商给出的模型 ID，不必从固定列表中选择。
3. 支持 OpenAI 兼容 Chat Completions 和 Anthropic Messages 两种接口。API 地址可以填基础地址或完整的 `/chat/completions`、`/messages` 地址。本机接口可用 `http://127.0.0.1:端口/v1`，远程接口使用 HTTPS。
4. 调整内置系统提示词后保存。密钥输入框留空保留原密钥，填写新值替换；可显式移除。更换服务地址的 origin 会清除旧密钥，避免把上一服务商的密钥交给下一服务商。
5. “保存并测试连接”只发送一条短测试消息，不含文稿。该操作仍可能产生服务商的 API 费用。
6. 在全局「阅读设置 → 选中文字后」开启「自动解释」，稳定选区会自动按照阅读系统提示词生成解释。若同时开启「写用户注释」，解释与输入框共用一个浮层；无须逐次点击或输入要求。手动细读与句法工作台仍可从左侧AI按钮打开并接收当前选区。

自动解释发送选区前后各最多100k字符的源文上下文以及选句，稳定边界与本地加密结果缓存服务重复阅读，具体见 [选区动作](selection-actions.md)。手动工作台的阅读请求仍发送完整 Markdown 源文、所选文本和本次要求；全文超出16 MB时拒绝发送，不静默截断。两个入口都不读取图片文件、解析外链或扫描其他本机文件。原文换行保留，应用字符数与模型token容量须分别理解。

句法模型默认收到句段及其前后各最多100k字符的上下文；也可选择仅发送句段。两套模型默认最大输出32768 tokens，思考模式与强度独立可调，接口返回的思考内容会流式显示。句法单次选区上限为12000 UTF-16字符，阅读选区上限64000，字符与tokens分别计数。

生成支持流式接收、停止、复制和另存。已有文字在网络错误或停止后仍可查看；达到输出上限会提示结果可能不完整。应用不自动重试付费请求，也不会把生成内容自动写回原文。改变文稿、重新开书、回阅读室或进入编辑会使旧选句失效，并停止相关请求。

## 句法光效

第17版改为常态呈现语言关系：明确的作用域嵌套、控制、跨句照应、模态与转述环境，不依赖正文悬停显示词性。`within`表达显式语义嵌套，前端不靠文字位置猜测；完整可见的短段落可共同分析相邻句子。详见 [让关系先于标签出现](syntax-reading-optics.md)。

新版以第二个模型作为完整的语言分析者。提示词处理核心依赖、否定与量化辖域、控制、省略、话题与焦点、指称及报告视角。应用附加v3逐行JSON契约，以units、relations、readings表达分层关系、不连续锚点、隐含单位和候选读法。每批完整关系一经校验便开始显影，不等待全篇结束。不同层允许重叠和交叉，原文定位仍逐字核对；隐含单位不会被插入原文。

全局「随阅读自动分析句法」开启且模型已配置时，连续可见十秒的正文句子进入后台队列，主动选区优先；初始光效约3.6秒柔缓出现。完成结果支持本地加密缓存，取消、错误和截断保留已校验部分。具体准入、参数、兼容范围与软件协议见 [随阅读逐批显影](ai-streaming.md)。

结果优先显示关系及依据，候选读法可明确切换；成分可展开查阅。旧v1片段输出继续兼容。未经校准的模型自评分不显示为正确率。光效升级为折光、潮汐与共鸣，由同一个组件服务正文和例句；没有实体端点或彩色实线。静谧和减少动态停止运动，关闭光效移除覆盖层，原文可选择、可编辑。

复制与另存生成包含原句、关系、依据和候选条件的 Markdown。完整规则与当前范围见 [关系、范围与读法](syntax-relationships.md)。
浏览器样机不接收真实 API 密钥。它提供明确标记为“固定例句、未调用模型”的光效示意；示意不会假装分析读者的文稿。真实连接在桌面程序的主进程中运行。

## 实现与验证边界

- 接口、凭据：`src/shared/ai-types.ts`、`src/main/ai/`、preload 的独立 `window.ai`。与原 `window.api` 的文稿读写契约分离。
- 密钥使用 Electron safeStorage；Windows 使用系统 DPAPI。系统保护不可用时，新密钥只保存在当前主进程内存中，不回落到明文磁盘。解密失败显示重新填写提示，不返回密钥给渲染层。系统保护不防御同一登录用户下所有恶意程序。
- 请求不接受重定向，不执行工具，不运行模型生成的 HTML、CSS 或脚本；响应作为纯文本或经过校验的 JSON 消费。API 错误正文不会直接展示，以免服务商回显凭据或源文。
- 请求与当前路径、完整源文快照和选句绑定；使用既有阅读选区的投影和地址。当前显示与文稿版本绑定，完成结果有精确键控制的加密缓存，不跨版本猜测迁移锚点。
- `tests/ai-syntax.test.ts` 测试重复词、Unicode、嵌套与失效数据；`tests/main/ai-config.test.ts` 测试密钥边界与独立配置；`tests/main/ai-transport.test.ts` 测试完整输入、两协议、UTF-8 流式边界、错误和截断。
- `tests/e2e/ai-reading.spec.ts` 通过本机 HTTP 测试服务验证真实主进程网络、IPC、用户设置与选句操作，不使用真实付费密钥。这能证明接线与界面行为，不是实际模型效果评测。

接口依据：[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[Chat Completions API](https://developers.openai.com/api/reference/resources/chat)、[Anthropic 流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)。服务商的模型名、额度和上下文容量以其实际接口为准。
