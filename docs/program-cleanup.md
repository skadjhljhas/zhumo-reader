# 卸载后的程序副本清理

40把可恢复移出之后的程序副本清理接到卸载器。文稿、设置和资料恢复点仍保留；不以递归删除安装根的方式回收空间。

## 归属来源

安装器只对自己新建的独立运行目录传入runtimeId。源目录、清单摘要、已知程序文件和卸载器的文件身份在首次安装时登记，引用与摘要随版本事务保存。通用更新调用者提供的source如果没有这项归属声明，不会因为曾经被读取就成为可清理对象。

清理候选来自已经完成或已经完整回滚的程序移出记录，以及这些版本对应的运行副本归属记录。读取计划时重新核对原清单、移出记录、来源身份及范围；改写计划无法把未知路径加入允许列表。

## 清理与保留

清理只对已登记、内容和文件身份仍符合预期的程序副本操作。新增文件、修改过的内容、链接和Markdown/EPUB阅读材料保留；当前绑定的文稿库也受到保护。纯文本程序许可证按程序清单处理，用户新增或修改的TXT仍保留。

资料保存点中的文稿和整份profile不会被拆解或删除。程序临时恢复目录里的已知程序副本可以回收，历史资料snapshot保持可用。程序目录中的未知内容保留，即使这使某些目录不能完全删除。

## 独立执行与重试

卸载器自带与发行包一致的运行环境，在自身的临时插件目录展开并校验。从这个独立环境运行最后清理，不依赖即将删除的旧bootstrap。旧卸载器文件在未被占用时也属于可核对的清理目标。

卸载完成与清理是两个阶段。v3卸载记录独立保存commit决定，原卸载完成回执供后续重试识别。清理持有覆盖安装根、profile和程序副本目录的准入，按文件实体、摘要逐项处理；新安装或系统登记已经改变时不继续旧计划。清理进程中断后，已有计划可以继续，已删除文件按缺失处理，不恢复旧文稿覆盖用户的新写作。

锁定、修改或不支持原生删除的文件会保留并写入结果记录。不会为了清理而终止用户正在使用的程序。运行环境被卸载器纳入自身文件，因此安装包/卸载器体积有所增加，换取不依赖原程序即可恢复和清理的能力。

## 验证记录

初轮18项安装、移除和清理检查通过；补充后的5项清理检查验证旧已回滚副本也可回收、通用source保留、篡改计划拒绝、文稿和设置保留，以及清理帮助进程真正退出后的继续执行。

真实NSIS最终验证使用复制的卸载器执行，模拟NSIS默认临时运行方式，避免测试的原地运行参数把待清理卸载器锁住。15.7分钟完整通过：撤回后中断恢复、清理、再安装、已提交中断后重试均通过；清掉476个旧程序文件副本（包含本次/此前已回滚的程序临时副本、受管bootstrap与旧卸载器），保留用户在runtime目录新增的Markdown和图片、原文件和后续71个profile文件。字体、加密配置与未命名草稿仍可用。

日志为 `work/setup40-native-cleanup.log`、`work/setup40-cleanup-units.log`、`work/setup40-cleanup-final.log`；完整JSON沿用 `work/setup32/managed-installer-evidence.json` 的历史路径，版本字段明确为40。窗口及资料目录隔离、隐藏，未操作用户日常候选中的文稿。

这项清理不会追溯认领没有运行目录归属声明的旧原型，也不删除资料snapshot中的内容。后者可能包含当时一起保存的旧程序，是保留的完整资料恢复点；不能以“释放全部占用”描述这种保留策略。正式配置身份与最终发布仍在继续。
