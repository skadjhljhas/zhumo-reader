# 更新数据保护：已验证的保存/恢复核心与剩余安装步骤

当前实现位于 `src/main/update-preservation.ts`。它是升级流程需要的保存/恢复组件，**尚未接入NSIS安装入口，不代表安装升级已安全完成**。当前用户桌面候选仍为21，本轮没有更换实际程序或修改用户资料。

## 保存点

`createPreservationSnapshot(sources, destination)` 要求显式绝对根路径和全新、父目录已存在的目标。保存点不得位于任何源根或关联链接目标内，源根也不能是整个盘符。函数不移动、删除或写入源文件。

每个普通文件使用原生文件复制并流式校验，记录SHA256、长度、修改时间与权限位；空目录也保留。所有来源重新枚举、重新读出比较，新增/删除/改名、内容改变和链接改向均不能悄悄通过。随后独立读回保存点中的每个文件核对。只有全部完成才从pending清单发布manifest.json。取消、异常、失联目录、损坏或中途中断留下未完成目录，不发布可用保存点。原生复制进行中需等当前文件复制结束才能响应取消，但不会继续到卸载。

候选24在真实Electron中改用original-fs操作实际磁盘，避免把app.asar解释成虚拟目录。本机也验证了命名流经过原生复制后保持；SHA256当前校验默认数据流，不把该项通过扩展为全部NTFS元数据验收。

符号链接和Windows Junction以图保存：目标内容作为独立根加入，每个canonical目标只排队一次，因此循环链接不会无限递归。保存点的payload本身不使用这些链接。失联链接明确失败，不把缺失目标当空目录。Windows文件符号链接恢复仍取决于系统授予的创建权限；目录Junction已在本机验证。

`verifyPreservationSnapshot` 不只读取成功标记，还验证清单结构和每个文件内容，拒绝路径穿越、重复路径、缺少目标的链接，以及把保存目录换成reparse point的情况。这里的校验用于检查意外损坏和结构一致性，不能替代正式发行包的签名与来源认证。

## 恢复副本

`restorePreservationSnapshot(snapshot, destination)` 只恢复到全新目录，不向现有配置或文稿目录叠加文件。先在同盘相邻的staging目录复制并读回校验，再发布完整目录；目标已存在则拒绝覆盖。修改时间恢复到毫秒精度，权限位恢复。失败的staging保留供检查，调用方不能把它视作完成。

所有链接指向恢复副本中的对应根，不指回仍在使用的真实文件。`recovery.json` 保留原路径与恢复根的对应关系。配置根整体恢复，Local State、模型密文和Chromium Local Storage一起保留，避免仅拷贝JSON导致密钥无法解密或主题偏好消失。

**调用前必须正常关闭相关读写程序并维持整个升级过程的写入隔离。** 双遍校验能发现采集期间的改变，不能代替停止写入的生命周期保证，也不是快照文件系统。此模块的成功只证明保存点可核验，不单独授权执行旧卸载器。

## 已获得的证据

- 8项保存/恢复专项单元检查：原程序与配置被模拟旧卸载删除后恢复原字节；BOM/CRLF、嵌套中文目录、空目录、未知图片资源、配置/Local State/LevelDB；Junction循环与恢复隔离；源变化与新增文件；取消；并发目标争用；保存点损坏；同名目标；链接失联、路径穿越与reparse替换。
- 全部480项单元检查通过，类型检查与新增文件ESLint通过。
- `tests/e2e/update-preservation.spec.ts` 使用实际候选21、隔离隐藏Electron。正常退出后保存整个profile，在另一目录恢复并启动：实际主题为潮光、字号23、注释透明度67及开关保持；原模型密文不变，safeStorage真正解密固定测试密钥成功；原文稿位置绑定保持；恢复的MD能打开且BOM/CRLF字节不变。原配置与原稿未修改，没有模型调用。
- 这个Electron检查是**关闭后的配置恢复**，不是NSIS安装升级；单元里的删除场景是临时目录模拟，不冒充旧安装器实际运行。

## 下一步必须接通的真实更新流程

1. 明确稳定版与AI预览的身份、待使用profile和旧安装位置。多个profile存在时保留双方，不能静默覆盖；文稿库的位置记录仍须尊重真实canonical目录。
2. 正常保存退出应用并确认写入进程停止，不通过强杀进程“完成”退出。为安装步骤保持独占，处理中途取消及重新启动的竞争。
3. 在运行旧卸载器之前用独立后台帮助程序建立并核验完整保存点。当前electron-builder模板的 `installSection.nsh` 在 `uninstallOldVersion` 之后才调用 `customInstall`，因此该宏来不及做保护。仅修改新 `customRemoveFiles` 也保护不了旧卸载器。
4. 将待装程序与用户文件分开处理，建立程序拥有的文件清单；恢复用户文稿、图片和未知文件时不覆盖冲突项。配置迁移必须保留整体加密上下文；跨路径恢复后，要显式处理库绑定及与路径有关的阅读记录，不能对所有JSON做盲目字符串替换。
5. 新卸载器只删除程序拥有的文件，不递归清掉混存数据。旧安装→新安装、便携更新、重装、跨目录、失联/只读/冲突、安装失败、中途断开、恢复和回滚仍须实际矩阵验证。发布门槛继续保持未通过。
