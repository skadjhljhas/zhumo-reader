# 安装侧的程序与系统入口联合恢复

安装验证38把 Windows 系统登记、快捷方式和安装回执接入原有版本事务。它仍是实验安装流程，不代表正式发布已经完成。

## 持久记录与提交顺序

带系统集成的安装使用第2版版本日志，保存安装配置、原登记状态和本次回执文件的身份；普通程序目录更新仍可使用第1版日志。旧恢复帮助程序会拒绝第2版，避免只恢复当前版本指针却遗漏系统登记。

取得资料保护、保存原文件并校验新版本后，切换当前指针。随后生成或复用快捷方式，更新并读回系统登记，写回安装回执；这些步骤全部完成后才保存 committed 状态并解除资料保护。

新快捷方式在公开之前，先保存本次发布意图及暂存文件的设备号和文件编号。公开路径与暂存文件采用非覆盖移动，因此进程在单个入口刚发布后退出，总记录即使尚未生成，恢复者也能核对该文件是否由这次安装创建。总记录同样完整暂存后再发布。

## 恢复行为

初次安装与异常退出后的恢复共用同一套集成函数。未提交的操作默认恢复旧程序入口和旧系统登记，并撤回本次新建且未被修改的快捷方式。复用的旧入口以及用户修改过的新入口保持原样。恢复操作不将旧文稿、字体或设置快照覆盖回现有目录。

安装/卸载命令入口读取同一安装中已退出写入者的持久状态。第2版已提交事务完成剩余收尾，其余恢复原状态后由新安装器实例继续安装；无法核对的旧事务不会被冒充为已完成系统恢复。

同一原始安装计划在提交后重试时返回该次安装的完成结果，不再次占用其回执文件。真实 NSIS 重新启动会产生新的独立运行目录；恢复完成后可继续这次新安装。

已提交标记保存在原文件核对、系统集成和回执验证之后。因此，提交之后用户继续编辑原稿或设置，不会导致恢复把这些新内容认作安装损坏。此时仍校验已安装程序的已知文件和系统入口；未知新增文件保留。

## 验证范围

20项相关检查已通过，包括原有安装/快捷方式回归，以及首次安装单个入口发布后退出、登记后退出、覆盖安装登记后退出、用户修改新入口后回滚、提交后同计划重试、显式继续完成未结束的首次安装。中断检查使用真正退出的 Node 帮助进程；该层替换原生资料锁生命周期，文件与注册表操作真实。

`tests/e2e/setup-install-recovery.spec.ts` 的真实NSIS与原生资料锁流程6.7分钟通过：首次安装的单个入口发布后退出、覆盖安装登记后退出，都由新的安装器实例联合恢复并完成；已提交的原始命令重试只收尾一次，保留其后新增的原稿。实际旧37帮助程序拒绝了第2版日志，当前指针未被它改变。无重复快捷方式。

同一38负载另跑完整安装/卸载回归，8.3分钟通过；字体、加密模型配置、未命名草稿、后续71个profile文件和新改稿保留，卸载两种中断重试与再安装仍可用。两条原生流程串行、隐藏并使用隔离目录，没有调用真实模型。
