# 细读着色：模型决定字色与荧光

本轮按用户的新要求，把默认标注从语法关系图改成两个独立颜色通道：模型决定哪些原词值得标注，以及每处的字色和荧光色。前端不根据“主语”“否定”“量词”等角色分配颜色，也不推导额外的语义嵌套。

默认提示词围绕哲学细读：概念的同一与转义、论证的转折与限制、作者承诺与转述之间的区别、否定/量化/模态的具体作用、使用与提及、指称与省略。它们是可选择的阅读方向，而非每句必须填完的分类表。用户可在模型设置中自由修改提示词和配色策略。

## 输出接口

系统提示词决定阅读策略；应用会另附一个简短格式契约。版本 4 逐条输出 JSON，完整的一条 `mark` 就能开始显影，无需等最后的 `done`。

```jsonl
{"type":"begin","version":4}
{"type":"mark","quote":"自由","occurrence":1,"textColor":"#386491","glowColor":"#e7bd91"}
{"type":"mark","quote":"自由","occurrence":2,"textColor":"#386491","glowColor":"#9ccfcb","note":"同一概念在后一句承担不同的论证作用。"}
{"type":"done","summary":"留意概念的复现与论证位置的变化。"}
```

上述颜色仅演示接口，不是内置语义色表。两个通道都可自由选色，不要求互补。软件只接受两个不同的 `#RRGGBB` 色号，不接受 CSS 表达式、HTML 或可执行代码。模型也会收到 `readingAppearance`，包含主题名、页面底色和正文字色，以便选择可读的配色。

- `quote` 必须与本次 `selectedText` 逐字一致。
- `occurrence` 从 1 开始，指这段引文在整个 `selectedText` 中的出现次数，含重叠出现。模型不用计算字符偏移。
- `id` 可选；用于修订前一条。没有 ID 时以原文位置作为身份。
- `note` 可选；在用户主动展开的着色依据中显示，不在正文悬停处弹出标签。
- 后一条覆盖重叠字符的两个通道；软件不会将两条标注混成第三种颜色。不想覆盖时应拆成互不重叠的引文。
- 也可用 `{"type":"patch","marks":[...]}` 批量发送，每批最多 48 条、一次目标最多 256 条。默认逐条发送更早可见。
- 没有值得标注的词句，可以直接正常结束，软件不会为了填满界面杜撰标注。

旧 v1/v2 完整结果与 v3 关系流保留兼容。旧版原封不动的内置提示词会迁到新默认；用户修改过的提示词、模型连接方式和密钥不被覆盖。用户自定义提示词若仍明确要求旧协议，需要按自己的阅读目的调整；应用设置可以恢复新默认。

## 定位、渲染与流式恢复

正式输出与思考通道分开。思考文字只供查看，不会被当成着色指令。一个 JSON 对象完整后，校验引文、出现次数、字素边界和色号，再提交。

字色通过 CSS Custom Highlights 应用于真实正文 Range，不新增包裹节点、复制字形或修改 Markdown。荧光由低透明背景与羽化的光晕构成，没有语法下划线、实体边框或成分弹签。标注从原始字色和无光状态约 2.6 秒柔缓进入目标状态；新批次不会重置旧批次的渐显。关闭光影时移除着色与荧光。

多次出现、跨行、粗体、链接和行内代码使用各自实际范围。公式以完整表达式作为原子对象绘制外部荧光；不向 KaTeX/MathJax 内部布局字形猜测字色，也不把透明占位字符染出来。模型在输出契约中能看到这个边界。

单条坏记录不终止后续有效记录。对于缺少闭合括号的 v4 `mark`，能在下一行明确的新记录头处恢复；不会把合法批量数组里的子对象误判成新根记录。已有有效颜色保留，坏流不冒充完整缓存。协议不替模型猜引文、色号或语言关系。

## 阅读调度与缓存

继续保留前台与实际可见范围要求。开始标注前的连续停留时间可在阅读设置中调为 1–15 秒，默认 5 秒；每个窗口最多 10 个句段并行分析，第 11 个满足条件的句段等待空位。前端调度、主进程接纳与界面说明共用同一个上限。显式选中仍可以优先调度。已完成目标按模型配置、提示词、输出契约、原文、上下文和阅读配色缓存；不完整结果不进入完整缓存。

默认上下文保留完整 Markdown；跟随模式还可选择目标前后各最多 100k 字符的窗口，或仅发送当前句段。全文标注通过独立提示词分析完整文稿与稳定文本块索引，并与跟随模式互斥，详见 [全文标注](whole-document-annotation.md)。代码模式可以直接编写请求体，简易模式保留通用配置；没有恢复 Qwen 专属思考长度开关。

第三个通道 `radiance` 为 0–1，省略或 0 表示普通荧光，正值表示「光华」。它与两个色号独立，HDR 下由全局浮点光层输出光冕、向上散射和柔和亮芯；原生文字和普通荧光仍各自定位。模型决定哪些词句值得使用。光华没有模型角色的固定色表，也不把重要性等同于命题为真。

主题或实际明暗模式变化后重新建立当前配色目标，防止将为深色背景选的浅字色直接搬到浅色背景。切回已有配色时仍可使用该主题的缓存。正在查看的旧手动结果可保留为分析文本，但不把不匹配当前主题的字色继续施加到正文。

## 代码与验证

默认提示词、颜色类型和校验：`src/shared/reading-colors.ts`。流式接收：`src/shared/syntax-stream.ts`。正文渲染：`components/ReadingColorLight.vue`。自动调度：`composables/automaticSyntax.ts`。请求与缓存：`src/main/ai/transport.ts`、`result-cache.ts`。

`tests/reading-colors.test.ts` 检查逐字定位、重复出现、覆盖规则、颜色自由度、坏记录隔离、未闭合记录恢复、字素边界及配色缓存身份。隐藏 Electron 检查见 `tests/e2e/reading-colors.spec.ts` 和 `reading-colors-mixed.spec.ts`：真实正文、流中显影、并发、重启缓存、两种主题、跨行/混排/重挂载及源文不变。

这些验证使用固定的本机 SSE 响应，只检查软件。按用户要求，不调用实际模型做能力验证，也不将固定接口通过宣称为哲学分析质量或最终美术已获认可。

回声与应用图标的视觉设计已按用户要求交接给 Claude Code；本接口与回声存储由 Codex 继续维护。
